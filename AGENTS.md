# Работа над исследованием

1. Начни с [вики проекта](docs/README.md) и [индекса исследования](docs/research/README.md). Открой только страницы, нужные для текущей задачи.
2. Для карты используй [описание этапа](docs/research/01-student-activity-map/README.md). Для разбора LMS используй [протокол наблюдений](docs/research/02-cu-lms-review/README.md).
3. Для требований к конкурсной работе сверяйся с [брифом](docs/brief.md), для сроков — с [календарём](docs/schedule.md).

## Как записывать результат

- Укажи основание каждого существенного утверждения: правило конкурса, личный опыт, наблюдение, интервью или гипотеза. ИИ-черновик помечай как гипотезу. Непроверенные детали работы LMS ЦУ записывай как вопросы.
- Используй относительные ссылки на конкретные материалы. Если вывод влияет на будущий выбор сценария, добавь его в [сводку](docs/research/findings.md) со ссылкой на основание.
- Записывай наблюдения о закрытых сервисах своими словами. Исключай персональные данные, учётные данные, закрытые файлы и скриншоты с идентифицирующими деталями.
- Сохраняй ключевые промпты и существенные исправления в [журнале ИИ](docs/research/ai-log.md). Обычно достаточно одной строки о результате и ссылки на материал.
- Актуальный этап и ближайший шаг смотри в [индексе исследования](docs/research/README.md). Изменения продуктового объёма фиксируй после решения владельца проекта. При передаче работы укажи, какие документы обновлены, на чём основаны выводы и какие вопросы остались.
